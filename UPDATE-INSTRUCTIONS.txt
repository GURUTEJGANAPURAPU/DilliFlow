OPERATOR WORKSPACE SETUP
------------------------
The commuter dashboard remains public. No account or sign-in is needed for
Journey Planner, Live Bus Map, Crowding Insights, Routes & Stops or Methodology.

Only /operator requires an operator ID and password.
From the project root, run:
  cd D:\DilliFlow
  Set-ExecutionPolicy -Scope Process Bypass
  .\configure_operator.ps1

Choose an operator ID and a password with at least 12 characters. The script
writes OPERATOR_ID and OPERATOR_PASSWORD to backend\.env and generates a random
OPERATOR_TOKEN_SECRET. It preserves your existing Transport Stack API key.
Restart FastAPI after the script completes. Keep backend\.env private and do
not commit it to GitHub.

CROWDING CAPACITY CONFIGURATION
-------------------------------
The ticket file does not contain verified fleet seat/standing capacities.
DilliFlow does not invent them. After operator sign-in, enter verified seat
and standing capacity for each route in the capacity configuration panel.
Only then does that route use Seats likely available / Standing room likely /
Crowded classifications. Until then, the commuter view shows relative
Low / Moderate / High ticket-demand levels and confidence/coverage information.
Only configure one route-level capacity when the vehicles operating that route
share the same verified capacity baseline.

IMPORTANT MODEL LIMITATIONS
---------------------------
- The per-bus value is estimated ticketed passengers per scheduled bus:
  median daily ticket journeys for a route/segment/hour divided by scheduled
  GTFS departures at the route origin/segment origin in that hour.
- It is not a sensor reading or verified total onboard occupancy.
- Ticket numbers can undercount all passengers; no undocumented expansion
  factor is applied. Vehicle number is missing from 48.52% of supplied ticket
  records, limiting vehicle-level validation.
- UP/DOWN direction is encoded in most route labels as separate GTFS route
  records; services without an explicit direction label are marked unknown.
- Stop names are partially matched. Confidence and coverage must remain visible.
- Capacity-based labels require actual, operator-verified capacity inputs.
